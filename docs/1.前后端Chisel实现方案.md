# WiredRV64S4 后端 Chisel 编码方案

本文档基于 [0.整体架构.md](/workspace/WiredRV/docs/0.整体架构.md) 给出可直接落地到当前代码结构的 Chisel 编码方案。当前前端、NPC、ICache refill、内部总线转换和外围 AXI 总线已经存在；本文重点描述 `Backend` 的三级流水、ALU、DCache、Store Queue、Scoreboard 和重定向实现。

## 1. 实现边界

当前代码边界如下：

- 前端接口使用 `Decoupled(new FetchPacket)`。
- 后端对前端输出 `Vec(3, Valid(UInt(p.addrBits.W)))` 重定向和 `ifencei`。
- 内部总线使用 `dayan.wiredrv.bus.BusBundle`，不是 TileLink。
- DCache 和 DCache refill/CMO 状态机直接实现在 `Backend` 模块内，风格对齐 `Frontend` 中 ICache 的写法。
- ALU 独立成组合模块，Backend 负责流水寄存器、前递、scoreboard、DCache 和状态更新。
- 后端为 D/E/W 三级，E/W 无阻塞，所有反压都收敛到 D 级 `io.inst.ready`。

建议文件组织：

```text
src/main/scala/wiredrv/backend/
  Backend.scala       # 后端顶层，直接包含 DCache、Store Queue、refill/CMO 状态机
  ALU.scala           # 新增，纯组合 ALU
  Decode.scala        # 已存在，继续使用
  DecodeDefs.scala    # 已存在，继续使用
  SBAllocator.scala   # 已存在，单分配、双释放
```

`Backend` 接口需要补充数据总线。模块接口不要额外定义只使用一次的接口 `Bundle`，直接写在模块内：

```scala
class Backend(implicit p: CoreParams) extends Module {
  val io = IO(new Bundle {
    val inst = Flipped(Decoupled(new FetchPacket))
    val redirects = Output(Vec(3, Valid(UInt(p.addrBits.W))))
    val ifencei = Output(Bool())
    val bus = new BusBundle(p.innerBusWidth)
  })

  // implementation...
}
```

顶层 `WiredCore` 后续应改为实例化 `Backend`，连接：

- `frontend.io.inst <> backend.io.inst`
- `frontend.io.redirects := backend.io.redirects`
- `frontend.io.ifencei := backend.io.ifencei`
- `backend.io.bus` 通过已有 `BusToAxi/AxiNarrowToWide` 接到数据侧 AXI 通路

## 2. 编码风格

整体代码保持简单、直接，优先让流水级关系清楚。不会重复使用的接口或只在一个模块里出现一次的数据结构，不单独抽 `Bundle`。模块接口一律优先写成：

```scala
val io = IO(new Bundle {
  val ...
})
```

只有以下情况建议定义独立 `Bundle`：

- 同一组字段会被多个寄存器、Wire 或函数复用，例如 `BackendUop`。
- SRAM 存储类型需要结构化字段，例如 `DCTag`。
- 队列项需要在多处读写和比较，例如 `StoreQueueEntry`。

Backend 顶层代码组织按固定顺序写：

```scala
class Backend(implicit p: CoreParams) extends Module {
  val io = IO(new Bundle { ... })

  // ============================================================
  // Registers and wires
  // ============================================================
  // 所有 Reg、Wire、模块例化、默认值集中放在最上面。

  // ============================================================
  // D stage
  // ============================================================
  // D 级 decode、RF read、hazard、vslot allocate、early redirect。

  // ============================================================
  // E stage
  // ============================================================
  // E 级 ALU/BRU、DCache hit、load forward、vslot release。

  // ============================================================
  // W stage
  // ============================================================
  // W 级 commit、RF write、redirect、Store Queue enqueue。

  // ============================================================
  // Store queue
  // ============================================================
  // Store Queue drain 和 mask 去重 next-state。

  // ============================================================
  // DCache refill and CMO
  // ============================================================
  // refill/CMO 状态机，完全接管 Cache。
}
```

信号命名按流水级加前缀：

- D 级组合信号使用 `d_`，例如 `d_fire`、`d_stall`、`d_rs1`。
- E 级组合信号使用 `e_`，例如 `e_hit`、`e_redirect`。
- W 级组合信号使用 `w_`，例如 `w_rfen`、`w_redirect`。
- 跨多个模块或全局结构可以不强制使用级名前缀，例如 `vAllocator`、`store_queue`、`dc_tags`。

注释要围绕“为什么这样写”和“这个块负责什么”，不要写机械重复的注释。推荐在每个流水级大块前写注释块，在复杂仲裁、flush、scoreboard release、Store Queue mask 去重处写短注释。

## 3. Backend 内部类型

建议在 `Backend.scala` 中只定义会重复使用的局部 Bundle，避免为了单次使用的接口增加层级。

### Micro-op

D 级 decode 后写入 E 级的最小单元：

```scala
class BackendUop(implicit p: CoreParams) extends Bundle {
  val pc = UInt(p.addrBits.W)
  val inst = UInt(32.W)
  val info = new DecodeInfo

  val rs1 = UInt(5.W)
  val rs2 = UInt(5.W)
  val rd = UInt(5.W)
  val imm = UInt(p.xlen.W)
  val csrAddr = UInt(12.W)
  val exceptionCode = UInt(16.W)

  val src1 = UInt(p.xlen.W)
  val src2 = UInt(p.xlen.W)
  val store_data = UInt(p.xlen.W)

  val flushed = Bool()
  val vslot_valid = Bool()
  val vslot = UInt(p.longLatencySlotsBits.W)
}
```

约束：

- `flushed` 由 D 级随 uop 打入 E 级。
- `vslot_valid/vslot` 记录 D 级是否已经分配不定延迟 scoreboard slot。
- 所有访存指令都设置 `vslot_valid`，普通 cachable hit 在 E 级释放。
- flushed uop 不产生 RF 写回、DCache 写入、重定向和架构状态更新，但需要释放已经分配的 vslot。

### DCache 元信息

DCache 采用 2-way，Tag/Data SRAM 直接实例化在 `Backend` 中：

```scala
class DCTag(implicit p: CoreParams) extends Bundle {
  val tag = UInt(p.dcacheTagBits.W)
  val dirty = Bool()
}

class StoreQueueEntry(implicit p: CoreParams) extends Bundle {
  val valid = Bool()
  val way = UInt(log2Ceil(p.dcacheWays).W)
  val idx = UInt((p.dcacheSetBits + log2Ceil(p.dcacheLineBytes / (p.xlen / 8))).W)
  val addr = UInt(p.addrBits.W)
  val mask = UInt((p.xlen / 8).W)
  val data = UInt(p.xlen.W)
  val set = UInt(p.dcacheSetBits.W)
}
```

`idx` 是 Data SRAM 写地址。若 Data SRAM 组织为每个 set 多个 64-bit word，则 `idx = set ## word`。若后续改成整行 SRAM，`idx` 可以替换为 set，entry 中保留 `word`。

### Refill/CMO 状态

Refill/CMO 状态机在 Backend 顶层实现：

```scala
object DCacheRefillState {
  val idle :: sendA :: recvD :: writeMeta :: cmoRead :: cmoWriteback :: cmoUpdate :: Nil = Enum(7)
}

val r_state = RegInit(DCacheRefillState.idle)
val r_pc = RegInit(0.U(p.addrBits.W))
val r_addr = RegInit(0.U(p.addrBits.W))
val r_line_addr = RegInit(0.U(p.addrBits.W))
val r_set = RegInit(0.U(p.dcacheSetBits.W))
val r_tag = RegInit(0.U(p.dcacheTagBits.W))
val r_way = RegInit(0.U(log2Ceil(p.dcacheWays).W))
val r_is_cmo = RegInit(false.B)
val r_cmo_op = RegInit(LSUOp.none)
```

这些寄存器只服务 refill/CMO 状态机，不额外定义 `DCacheRefillReq` Bundle。

## 4. ALU 模块

新增 `ALU.scala`，纯组合逻辑：

```scala
class ALU(implicit p: CoreParams) extends Module {
  val io = IO(new Bundle {
    val src1 = Input(UInt(p.xlen.W))
    val src2 = Input(UInt(p.xlen.W))
    val op = Input(UInt(AluOp.width.W))
    val out = Output(UInt(p.xlen.W))
  })

  // Shared operands for shift and word operations.
  val shamt = io.src2(5, 0)
  val shamtw = io.src2(4, 0)
  val add = io.src1 + io.src2
  val sub = io.src1 - io.src2
  val word = WireDefault(0.U(32.W))

  io.out := 0.U
  switch(io.op) {
    is(AluOp.add)  { io.out := add }
    is(AluOp.sub)  { io.out := sub }
    is(AluOp.sll)  { io.out := io.src1 << shamt }
    is(AluOp.slt)  { io.out := (io.src1.asSInt < io.src2.asSInt).asUInt }
    is(AluOp.sltu) { io.out := io.src1 < io.src2 }
    is(AluOp.xor)  { io.out := io.src1 ^ io.src2 }
    is(AluOp.srl)  { io.out := io.src1 >> shamt }
    is(AluOp.sra)  { io.out := (io.src1.asSInt >> shamt).asUInt }
    is(AluOp.or)   { io.out := io.src1 | io.src2 }
    is(AluOp.and)  { io.out := io.src1 & io.src2 }
    is(AluOp.copy1){ io.out := io.src1 }
    is(AluOp.copy2){ io.out := io.src2 }
  }

  switch(io.op) {
    is(AluOp.addw) { word := io.src1(31, 0) + io.src2(31, 0); io.out := Cat(Fill(32, word(31)), word) }
    is(AluOp.subw) { word := io.src1(31, 0) - io.src2(31, 0); io.out := Cat(Fill(32, word(31)), word) }
    is(AluOp.sllw) { word := io.src1(31, 0) << shamtw; io.out := Cat(Fill(32, word(31)), word) }
    is(AluOp.srlw) { word := io.src1(31, 0) >> shamtw; io.out := Cat(Fill(32, word(31)), word) }
    is(AluOp.sraw) { word := (io.src1(31, 0).asSInt >> shamtw).asUInt; io.out := Cat(Fill(32, word(31)), word) }
  }
}
```

后续可以把 repeated sign-extension 抽成 helper，但首版建议保持直白。

## 5. 顶层寄存器、Wire 和默认连接

`Backend` 顶部先集中放寄存器、Wire、模块例化和默认值，避免在各流水级中间来回声明。

寄存器和模块例化示意：

```scala
// ============================================================
// Registers and wires
// ============================================================
val rf = Reg(Vec(32, UInt(p.xlen.W)))
val e_valid = RegInit(false.B)
val e_uop = RegInit(0.U.asTypeOf(new BackendUop))
val w_valid = RegInit(false.B)
val w_uop = RegInit(0.U.asTypeOf(new BackendUop))

val vAllocator = Module(new SBAllocator)
val alu = Module(new ALU)
```

然后给所有输出默认值，避免未连接：

```scala
io.redirects.foreach { r =>
  r.valid := false.B
  r.bits := 0.U
}
io.ifencei := false.B

io.bus.a.valid := false.B
io.bus.a.bits := 0.U.asTypeOf(io.bus.a.bits)
io.bus.d.ready := false.B
```

`SBAllocator` 两个释放口也要有默认值：

```scala
vAllocator.io.allocate.ready := false.B
vAllocator.io.release.foreach { r =>
  r.valid := false.B
  r.bits := 0.U
}
```

RF 写回默认：

```scala
w_rfen := false.B
w_rfdata := 0.U
w_rd_next := 0.U

v_rfen := false.B
v_rf := 0.U
v_rfdata := 0.U
```

实际编码时建议用 `w_uop.rd` 作为 W 级流水寄存器中的 rd，而不是单独 `w_rd_next`；这里的名字只表达连接意图。

## 6. 流水寄存器

E/W 无阻塞，因此只需要 valid 和 bits 寄存器：

```scala
val e_valid = RegInit(false.B)
val e_uop = RegInit(0.U.asTypeOf(new BackendUop))
val w_valid = RegInit(false.B)
val w_uop = RegInit(0.U.asTypeOf(new BackendUop))

val e_redirect = Wire(Valid(UInt(p.addrBits.W)))
val w_redirect = Wire(Valid(UInt(p.addrBits.W)))
```

每周期推进规则：

```scala
val older_redirect = e_redirect.valid || w_redirect.valid
val d_fire = io.inst.valid && io.inst.ready

w_valid := e_valid && !e_uop.flushed && !w_redirect.valid
w_uop := e_uop

when(d_fire) {
  e_valid := true.B
  e_uop := d_make_uop
}.otherwise {
  e_valid := false.B
  e_uop := 0.U.asTypeOf(new BackendUop)
}
```

注意：

- D stall 时 E 写入 bubble，W 继续吃上一拍 E。
- W 级重定向时，当前 E 级更年轻指令被杀，下一拍不能进入 W。
- D fire 且 E/W 同拍重定向时，`d_make_uop.flushed := true.B`，仍写入 E，以便 E 级释放 vslot。
- 如果 refill/CMO 状态机 busy，D stall，E/W 应该已经被前一拍 W redirect 清空；实现上仍按 bubble 推进。

`d_make_uop.flushed`：

```scala
val d_flushed = d_fire && older_redirect
d_make_uop.flushed := d_flushed
```

## 7. D 级编码

### Decode 和 RF 读取

Decode 使用现有 `Decode`：

```scala
val decoder = Module(new Decode)
decoder.io.inst := io.inst.bits.inst
val d_dec = decoder.io.out
```

需要把 PC 补入 decoded 信息：

```scala
val d_pc = io.inst.bits.pc
```

RF 读取先处理 x0，再只做 W 固定延迟写回前递：

```scala
def rf_read(reg: UInt): UInt = Mux(reg === 0.U, 0.U, rf(reg))

def d_forward(reg: UInt, data: UInt): UInt =
  Mux(w_rfen && w_uop.rd === reg && reg =/= 0.U, w_rfdata, data)

val d_rs1_rf = rf_read(d_dec.rs1)
val d_rs2_rf = rf_read(d_dec.rs2)
val d_rd_rf  = rf_read(d_dec.rd)

val d_rs1 = d_forward(d_dec.rs1, d_rs1_rf)
val d_rs2 = d_forward(d_dec.rs2, d_rs2_rf)
val d_rd  = d_forward(d_dec.rd, d_rd_rf)
```

不定延迟写回口不参与前递；不应把 `v_rfen/v_rfdata` 放入 `d_forward`。

JR/JALR 目标计算必须使用 RF 中已经就绪的数据：

```scala
val d_jr_base = d_rs1_rf
```

只要 `rs1` 命中 E/W 或不定延迟 scoreboard，JR/JALR 就 stall，因此 `d_rs1_rf` 是正确值。

### 源操作数选择

```scala
def select_src(sel: UInt, regData: UInt, pc: UInt, imm: UInt): UInt = {
  MuxLookup(sel, 0.U)(Seq(
    SrcType.reg -> regData,
    SrcType.pc  -> pc,
    SrcType.imm -> imm
  ))
}

val d_src1 = select_src(d_dec.info.src1Type, d_rs1, d_pc, d_dec.imm)
val d_src2 = select_src(d_dec.info.src2Type, d_rs2, d_pc, d_dec.imm)
```

Store data 单独保存 `d_rs2`，后续 E 级可从 W 级固定写回口再前递一次。

### Scoreboard 状态

固定延迟 scoreboard 建议直接由 E/W 流水有效位派生：

```scala
val e_fixed_valid = e_valid && !e_uop.flushed && e_uop.info.rwen && e_uop.rd =/= 0.U
val w_fixed_valid = w_valid && !w_uop.flushed && w_uop.info.rwen && w_uop.rd =/= 0.U
```

不定延迟 scoreboard：

```scala
val v_valid = RegInit(VecInit(Seq.fill(p.longLatencySlots)(false.B)))
val v_gpr = Reg(Vec(p.longLatencySlots, UInt(5.W)))
```

命中函数：

```scala
def hit_fixed_e(reg: UInt): Bool = e_fixed_valid && e_uop.rd === reg && reg =/= 0.U
def hit_fixed_w(reg: UInt): Bool = w_fixed_valid && w_uop.rd === reg && reg =/= 0.U
def hit_var(reg: UInt): Bool =
  reg =/= 0.U && VecInit((0 until p.longLatencySlots).map(i => v_valid(i) && v_gpr(i) === reg)).asUInt.orR
```

### 是否需要分配 vslot

按照文档0，所有访存指令都分配不定延迟 slot。其它长延迟指令后续也走同一路：

```scala
val d_need_vslot = d_dec.info.isLsu // 后续扩展: || d_is_muldiv || d_is_atomic || d_is_uncached_only
```

分配在 D fire 时发生，即使当前 D 指令会被同拍 E/W redirect flush：

```scala
vAllocator.io.allocate.ready := d_fire && d_need_vslot
val d_vslot = vAllocator.io.allocate.bits
```

D fire 后写 scoreboard：

```scala
when(d_fire && d_need_vslot && d_dec.info.rwen && d_dec.rd =/= 0.U) {
  v_valid(d_vslot) := true.B
  v_gpr(d_vslot) := d_dec.rd
}
```

Store/CMO 没有 GPR 写回，但仍可能需要 vslot 用于统一释放路径。若后续确认 store 不需要占用 v_gpr，可以保留 `vslot_valid` 但不置 `v_valid`；首版建议 vslot 和 v_valid 分开：

- `vslot_valid`：allocator token 是否需要释放。
- `v_valid`：该 token 是否参与 GPR RAW/WAW 比较。

### D stall 条件

基础条件：

```scala
val d_uses_rs1 = d_dec.info.rs1en
val d_uses_rs2 = d_dec.info.rs2en
val d_writes_rd = d_dec.info.rwen && d_dec.rd =/= 0.U

val d_is_jal = d_dec.info.fuType === FuType.jmp && d_dec.info.fuOpType === BruOp.jal
val d_is_jalr = d_dec.info.fuType === FuType.jmp && d_dec.info.fuOpType === BruOp.jalr
val d_is_jr = d_is_jalr
```

RAW/WAW：

```scala
val d_rs1_var_haz = d_uses_rs1 && hit_var(d_dec.rs1)
val d_rs2_var_haz = d_uses_rs2 && hit_var(d_dec.rs2)
val d_rd_var_haz = d_writes_rd && hit_var(d_dec.rd)

val d_lsu_addr_e_haz = d_dec.info.isLsu && d_uses_rs1 && hit_fixed_e(d_dec.rs1)
val d_jr_not_ready = d_is_jr && d_uses_rs1 &&
  (hit_fixed_e(d_dec.rs1) || hit_fixed_w(d_dec.rs1) || hit_var(d_dec.rs1))

val d_no_vslot = d_need_vslot && !vAllocator.io.allocate.valid
val d_cache_busy = refill_busy
val d_uncached_busy = uncached_busy

val d_stall =
  d_rs1_var_haz || d_rs2_var_haz || d_rd_var_haz ||
  d_lsu_addr_e_haz || d_jr_not_ready ||
  d_no_vslot || d_cache_busy || d_uncached_busy

io.inst.ready := !d_stall
```

注意：

- JR/JALR 不允许使用 W 级前递，命中 W fixed 也 stall。
- 普通 ALU/branch/store data 命中 E fixed 不 stall，E 级通过 W 前递解决。
- Load 地址源命中 E fixed 必须 stall，因为 D 级要用地址访问 DCache SRAM。

### D 级早期重定向

```scala
val d_jal_target = d_pc + d_dec.imm
val d_jalr_target = (d_jr_base + d_dec.imm) & ~(1.U(p.addrBits.W))
val d_jump_target = Mux(d_is_jalr, d_jalr_target, d_jal_target)

val d_early_redirect = Wire(Valid(UInt(p.addrBits.W)))
d_early_redirect.valid := d_fire && !d_flushed && (d_is_jal || d_is_jalr)
d_early_redirect.bits := d_jump_target

io.redirects(2) := d_early_redirect
```

如果 E/W 同拍重定向，`d_flushed` 禁止 D 级重定向，但 D fire 仍可分配 scoreboard 并把 flushed uop 打入 E。

## 8. E 级编码

### W 级前递到 E

E 级需要对从 D 级带来的 `src1/src2/store_data` 再做一次 W 固定写回口前递：

```scala
def e_forward(reg: UInt, data: UInt): UInt =
  Mux(w_rfen && w_uop.rd === reg && reg =/= 0.U, w_rfdata, data)

val e_src1 = e_forward(e_uop.rs1, e_uop.src1)
val e_src2 = e_forward(e_uop.rs2, e_uop.src2)
val e_store_data = e_forward(e_uop.rs2, e_uop.store_data)
```

JR/JALR 目标不在 E 级计算；D 级已处理。

### ALU 和 BRU

ALU：

```scala
val alu = Module(new ALU)
alu.io.src1 := e_src1
alu.io.src2 := e_src2
alu.io.op := e_uop.info.fuOpType(AluOp.width - 1, 0)
val e_alu_out = alu.io.out
```

Branch：

```scala
val e_eq = e_src1 === e_src2
val e_lt = e_src1.asSInt < e_src2.asSInt
val e_ltu = e_src1 < e_src2

val e_branch_taken = MuxLookup(e_uop.info.fuOpType, false.B)(Seq(
  BruOp.beq  -> e_eq,
  BruOp.bne  -> !e_eq,
  BruOp.blt  -> e_lt,
  BruOp.bge  -> !e_lt,
  BruOp.bltu -> e_ltu,
  BruOp.bgeu -> !e_ltu
))

e_redirect.valid := e_valid && !e_uop.flushed &&
  e_uop.info.fuType === FuType.bru && e_branch_taken
e_redirect.bits := e_uop.pc + e_uop.imm
io.redirects(1) := e_redirect
```

### DCache 命中判断

D 级发起 SRAM 读：

```scala
val d_addr = d_rs1 + d_dec.imm
val d_dcache_set = p.dcacheGetSet(d_addr)
val d_dcache_word = d_addr(p.dcacheLineBits - 1, log2Ceil(p.xlen / 8))
```

当前 `CoreParams` 还没有 `dcacheGetSet/GetTag/GetWord` helper，建议补齐：

```scala
def dcacheGetTag(addr: UInt): UInt = addr(addrBits - 1, dcacheSetBits + dcacheLineBits)
def dcacheGetSet(addr: UInt): UInt = addr(dcacheSetBits + dcacheLineBits - 1, dcacheLineBits)
def dcacheGetWord(addr: UInt): UInt = addr(dcacheLineBits - 1, log2Ceil(xlen / 8))
```

Tag/Data SRAM：

```scala
val dc_valid = RegInit(0.U.asTypeOf(Vec(p.dcacheWays, Vec(p.dcacheSets, Bool()))))
val dc_tags = Seq.fill(p.dcacheWays)(Module(new SRAMTemplate(new DCTag, p.dcacheSets, singlePort = true)))
val dc_datas = Seq.fill(p.dcacheWays)(
  Module(new SRAMTemplate(UInt(p.xlen.W), p.dcacheSets * (p.dcacheLineBytes / (p.xlen / 8)), singlePort = true))
)
```

访问优先级：

1. refill/CMO 状态机接管。
2. D 级 load 正常读 Tag/Data SRAM。
3. Store Queue 在 Data SRAM 空闲时写 Data SRAM。
4. D 级 store 不读 Data SRAM，只需要 Tag SRAM 判断命中；因此 D 级 store 发射周期 Data SRAM 对 Store Queue 是空闲的。

E 级 hit：

```scala
val e_set = RegEnable(d_dcache_set, d_fire)
val e_tag = RegEnable(p.dcacheGetTag(d_addr), d_fire)
val e_addr = RegEnable(d_addr, d_fire)

val e_way_hits = VecInit((0 until p.dcacheWays).map { i =>
  dc_valid(i)(e_set) && dc_tags(i).io.r.resp.data(0).tag === e_tag
})
val e_hit = e_way_hits.asUInt.orR
val e_hit_way = PriorityEncoder(e_way_hits)
```

### Load 数据处理和 Store Forward

Load 从 Data SRAM 读出 64-bit word 后，先做 Store Forward，再做字节/半字/字符号扩展。

三个 forward 源：

```scala
val w_store_forward = Wire(new StoreQueueEntry)
val sq0 = store_queue(0)
val sq1 = store_queue(1)
```

合并函数：

```scala
def merge_by_mask(base: UInt, fwd_data: UInt, mask: UInt): UInt = {
  val bytes = Wire(Vec(p.xlen / 8, UInt(8.W)))
  for (i <- 0 until p.xlen / 8) {
    bytes(i) := Mux(mask(i), fwd_data(8 * i + 7, 8 * i), base(8 * i + 7, 8 * i))
  }
  bytes.asUInt
}

def store_hit_load(s: StoreQueueEntry, load_addr: UInt): Bool =
  s.valid && s.addr(p.addrBits - 1, log2Ceil(p.xlen / 8)) === load_addr(p.addrBits - 1, log2Ceil(p.xlen / 8))
```

优先级：

- Store Queue 内同地址 entry mask 已不重叠，顺序不影响不重叠 byte。
- W store 是最新提交结果，若和 SQ mask 重叠，W store 覆盖 SQ。

```scala
val after_sq0 = Mux(store_hit_load(sq0, e_addr), merge_by_mask(cache_word, sq0.data, sq0.mask), cache_word)
val after_sq1 = Mux(store_hit_load(sq1, e_addr), merge_by_mask(after_sq0, sq1.data, sq1.mask), after_sq0)
val after_w_store = Mux(store_hit_load(w_store_forward, e_addr), merge_by_mask(after_sq1, w_store_forward.data, w_store_forward.mask), after_sq1)
```

Load 扩展：

```scala
def load_extend(word: UInt, addr: UInt, op: UInt): UInt = {
  val byte = word >> (addr(2, 0) << 3)
  val half = word >> (addr(2, 1) << 4)
  val w = word >> (addr(2) << 5)
  MuxLookup(op, word)(Seq(
    LSUOp.lb  -> Cat(Fill(56, byte(7)), byte(7, 0)),
    LSUOp.lbu -> Cat(0.U(56.W), byte(7, 0)),
    LSUOp.lh  -> Cat(Fill(48, half(15)), half(15, 0)),
    LSUOp.lhu -> Cat(0.U(48.W), half(15, 0)),
    LSUOp.lw  -> Cat(Fill(32, w(31)), w(31, 0)),
    LSUOp.lwu -> Cat(0.U(32.W), w(31, 0)),
    LSUOp.ld  -> word
  ))
}
```

### Store mask/data 生成

```scala
def store_mask(addr: UInt, op: UInt): UInt = {
  val off = addr(log2Ceil(p.xlen / 8) - 1, 0)
  MuxLookup(op, 0.U((p.xlen / 8).W))(Seq(
    LSUOp.sb -> (1.U << off),
    LSUOp.sh -> (3.U << off),
    LSUOp.sw -> ("hf".U << off),
    LSUOp.sd -> "hff".U
  ))
}

def store_data(data: UInt, addr: UInt): UInt = {
  data << (addr(log2Ceil(p.xlen / 8) - 1, 0) << 3)
}
```

E 级只生成 store queue entry 候选，真正入队在 W 级提交点。

### E 级释放 vslot

`release(0)` 固定为 E 级本地释放端口：

```scala
val e_release_vslot =
  e_valid && e_uop.vslot_valid &&
  (e_uop.flushed || (e_uop.info.isLsu && e_hit && !e_is_long_latency))

vAllocator.io.release(0).valid := e_release_vslot
vAllocator.io.release(0).bits := e_uop.vslot
```

`e_is_long_latency` 包括 uncached、真正 miss 后需要保留的长延迟路径等。普通 cachable hit load/store 在 E 级释放。

若 `w_redirect.valid` 同拍成立，当前 E uop 也会走 `e_uop.flushed` 或由额外条件触发 release。建议条件写成：

```scala
val e_killed_by_w = w_redirect.valid && e_valid
val e_release_vslot = e_valid && e_uop.vslot_valid &&
  (e_uop.flushed || e_killed_by_w || e_cachable_hit_no_long_latency)
```

## 9. W 级编码

### 写回数据选择

W 级寄存 E 级结果：

```scala

val w_load_data = Reg(UInt(p.xlen.W))
val w_store_entry = Reg(new StoreQueueEntry)
val w_hit = Reg(Bool())
val w_miss = Reg(Bool())
```

写回数据：

```scala
w_rfdata := Mux(w_uop.info.isLsu, w_load_data,
            Mux(w_uop.info.fuType === FuType.jmp, w_uop.pc + 4.U, w_result))
w_rfen := w_valid && !w_uop.flushed && w_uop.info.rwen && w_uop.rd =/= 0.U && !w_miss

when(w_rfen) {
  rf(w_uop.rd) := w_rfdata
}
```

miss/replay 时本条指令不写 RF。

### W 重定向

W 重定向优先级最高：

```scala
w_redirect.valid := false.B
w_redirect.bits := 0.U

when(w_valid && !w_uop.flushed) {
  when(w_miss) {
    w_redirect.valid := true.B
    w_redirect.bits := w_uop.pc
  }.elsewhen(w_is_cmo) {

  }

```

CMO 本身启动状态机后从 `pc + 4` 继续。

### Store Queue 入队

W 级 cached hit store 确认提交后入队：

```scala
val w_store_commit = w_valid && !w_uop.flushed && w_uop.info.isStore && w_hit && !w_miss
```

入队前先更新老 entry mask：

```scala
for (i <- 0 until 2) {
  when(w_store_commit && store_queue(i).valid && same_store_addr(store_queue(i), w_store_entry)) {
    store_queue(i).mask := store_queue(i).mask & ~w_store_entry.mask
    when((store_queue(i).mask & ~w_store_entry.mask) === 0.U) {
      store_queue(i).valid := false.B
    }
  }
}
```

然后把新 store 写入空 entry。因为同周期可能有 Store Queue drain，需要先计算 next valid，避免误判 full。建议把 SQ 更新写成一个小的组合 next-state，而不是多处 `when` 覆盖。

## 10. Store Queue 编码

Store Queue 两项寄存器：

```scala
val store_queue = RegInit(VecInit(Seq.fill(2)(0.U.asTypeOf(new StoreQueueEntry))))
```

工具函数：

```scala
def same_store_addr(a: StoreQueueEntry, b: StoreQueueEntry): Bool =
  a.addr(p.addrBits - 1, log2Ceil(p.xlen / 8)) === b.addr(p.addrBits - 1, log2Ceil(p.xlen / 8))

val sq_full = store_queue.map(_.valid).reduce(_ && _)
```

写入 Data SRAM 条件：

```scala
val d_dcache_data_read = d_fire && d_dec.info.isLsu && !d_dec.info.isStore && !d_is_cmo
val sq_can_drain = !refill_busy && !d_dcache_data_read
val sq_drain_idx = Mux(store_queue(0).valid, 0.U, 1.U)
val sq_drain = sq_can_drain && (store_queue(0).valid || store_queue(1).valid)
```

当 `sq_drain`：

- 向命中 way 的 Data SRAM 写 `data/mask`。
- 清除该 entry。
- 如果 entry1 仍有效，可选择不压缩，保持两项无序；入队查找空项即可。

Data SRAM 单端口仲裁规则：

1. refill/CMO 状态机。
2. D 级 load 正常读。
3. Store Queue drain，仅在 Data SRAM 没有被 D 级 load 使用时发生。

注意：D 级 store 不读取 Data SRAM，因此当连续 store 发射时，SQ drain 可与 D 级 store 同拍发生。

## 11. DCache Refill/CMO 状态机

### 启动

启动来源在 W 级：

```scala
val start_refill = w_valid && !w_uop.flushed && w_miss && !w_is_uncached
val start_cmo = w_valid && !w_uop.flushed && w_is_cmo
```

启动时：

- 写入 `r_pc`、`r_addr`、`r_line_addr` 等状态寄存器。
- `refill_busy := true.B`。
- 设置 `r_state := sendA` 或 CMO 初态。
- W 级发出 `redirects(0)`。

### Bus 读请求

参考 Frontend：

```scala
io.bus.a.valid := r_state === DCacheRefillState.sendA && r_a_valid
io.bus.a.bits.address := r_line_addr
io.bus.a.bits.op := BusOp.ReadOnly
io.bus.a.bits.size := log2Ceil(p.dcacheLineBytes).U
io.bus.a.bits.mask := Fill(p.innerBusWidth / 8, 1.U)
io.bus.a.bits.data := 0.U
io.bus.a.bits.id := 1.U

when(io.bus.a.fire) { r_a_valid := false.B }
```

响应写 Data SRAM：

```scala
io.bus.d.ready := r_state === DCacheRefillState.recvD
when(io.bus.d.fire) {
  dc_datas(r_way).io.w.req.valid := true.B
  dc_datas(r_way).io.w.req.bits.apply(io.bus.d.bits.data, write_idx, Fill(p.innerBusWidth / 8, 1.U))
  beat_cnt := beat_cnt + 1.U
}
```

当前 `BusBundle` 数据宽度可能是 32 bit，而 DCache Data SRAM word 是 64 bit。两种实现可选：

- 把 DCache Data SRAM word 做成 `p.innerBusWidth` 宽度，load 时拼回 XLEN。
- 保持 64-bit word，refill 时用两个 32-bit beat 拼成 64-bit 后写。

首版建议让 DCache Data SRAM 宽度等于 `p.innerBusWidth`，减少 refill 拼接逻辑；load 64-bit 再由两个 word 组合。若要保持 `UInt(p.xlen.W)`，必须实现 half-word buffer。

### CMO

CMO 状态机接管 Tag/Data SRAM：

- `CBO.INVAL`：命中则清 valid。
- `CBO.CLEAN`：dirty 命中则逐 beat 发 StoreOnly 写回，完成后清 dirty。
- `CBO.FLUSH`：dirty 命中先写回，随后清 valid/dirty。

若首版暂不支持 dirty：

- `CBO.CLEAN` no-op。
- `CBO.FLUSH` invalidate。
- 文档和代码注释要明确这是 write-through 或 no-dirty 过渡实现。

## 13. Redirect 和 flush 汇总

三路输出：

```scala

```

`d_flushed`：

```scala

```

E 级被 W 杀：

```scala

```

所有副作用信号都要 gate：


这包括：

- RF 写回。
- Store Queue 入队。
- DCache tag/data 修改。
- CMO/refill 启动。
- redirect 生成。
- vslot 是否保留为长延迟。

但 E 级 vslot 释放不受 `e_can_side_effect` 限制；被杀指令仍要释放已分配 slot。

## 15. 高风险点

- `SBAllocator.allocate.valid` 表示有空闲 slot，D stall 条件应是 `d_need_vslot && !allocate.valid`。
- JR/JALR 不能使用 W 前递，命中 E/W fixed 或 v scoreboard 都要 stall。
- D fire 且 E/W redirect 时仍要分配 vslot，并把 `flushed` 打到 E 级释放。
- `release(0)` 是 E 本地释放，`release(1)` 是长延迟写回释放，不要混用。
- Store Queue 同地址 mask 必须去重，否则 E load forward 需要处理同地址多版本重叠字节。
- W store 是三个 load-forward 源中最新的源，重叠 byte 要覆盖 SQ。
- refill/CMO busy 时必须完全接管 DCache，并阻塞后端流水。
- Store Queue drain 不能和 D 级 load 抢同一个 Data SRAM 端口；它只在 Data SRAM 对 load 空闲时发生。
- W redirect 杀 E 时，E 不得产生副作用，但要释放自己的 vslot。
