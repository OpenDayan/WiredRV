# WiredRV64S4 前后端 Chisel 实现方案

本文基于 [0.整体架构.md](/workspace/WiredRV/docs/0.整体架构.md) 和最新约束重新收敛，实现目标是给出适合当前标量核的 Chisel 落地方案，而不是保留面向通用处理器的冗余抽象。

## 1. 设计边界

- 核类型：单发射标量核。
- 前端每周期最多取回 1 条指令。
- 不支持压缩指令 `C`。
- 不支持虚拟地址，不实现 TLB。
- ICache / DCache 固定 `2-way`。
- 外部总线直接使用 `TileLink-UH`。
- Difftest 必须完整实例化 `Test.scala` 中已有的 5 个 `DifftestModule`。

## 3. 参数与区域配置

建议统一在 `Parameters.scala` 中定义：

```scala
case class AddrRegion(base: BigInt, size: BigInt)

case class CoreParams(
  xlen: Int = 64,
  addrBits: Int = 40,
  resetPc: BigInt = 0x80000000L,
  icacheSets: Int = 64,
  icacheWays: Int = 2,
  icacheLineBytes: Int = 16,
  dcacheSets: Int = 64,
  dcacheWays: Int = 2,
  dcacheLineBytes: Int = 16,
  storeQueueDepth: Int = 4,
  longLatencySlots: Int = 3,
  cachedRegions: Seq[AddrRegion] = Seq(AddrRegion(0x80000000L, 0x10000000L)),
  uncachedRegions: Seq[AddrRegion] = Seq(AddrRegion(0x00000000L, 0x80000000L))
)
```

这里直接把 cached / uncached 区域作为顶层参数传入，供：

- D 级做 uncached 区域判定。
- ICache / DCache 判断是否允许走 cache 通路。
- 后续外设地址空间扩展时复用。

## 4. 公共 Bundle 设计

## 4.1 前端输出

前端给后端的包按你的要求收敛为：

```scala
class FetchPacket(implicit p: CoreParams) extends Bundle {
  val pc = UInt(p.addrBits.W)
  val inst = UInt(32.W)
  val jump = Bool()
  val target = UInt(p.addrBits.W)
}
```

字段语义：

- `pc`：当前指令地址。
- `inst`：指令字。
- `jump`：前端预测本条取到的指令后续会改变控制流。
- `target`：预测跳转目标；无预测时可填 `pc + 4`。

这里前端不向后端传递 miss 信息。取指 miss 由前端内部消费：

- 前端 miss 时，阻塞取指推进。
- `IRefill` 发起重填。
- refill 完成后由前端自行发起 miss replay redirect。

后端只看到真实取到的指令流，不需要感知前端 miss。

## 4.2 Redirect 请求

不再携带 `flushFrontend/flushBackend` 信号，刷流水范围由流水线本身按来源决定：

```scala
object RedirectCause {
  val frontendMissReplay :: jumpEarlyDecode :: exuFlush :: backendReplayOrException :: nlp :: Nil = Enum(5)
}

class RedirectReq(implicit p: CoreParams) extends Bundle {
  val target = UInt(p.addrBits.W)
  val cause = UInt(3.W)
}
```

其中 `nlp` 先预留编码，当前实现可以不接。

`jump/target` 字段保留的意义是允许前端未来接入分支预测。但当前版本明确约束如下：

- 当前版本不实现分支预测器。
- 当前版本不需要后端到前端的分支预测更新接口。
- `jump` 缺省为 `false.B`。
- `target` 缺省为 `pc + 4`。

后续如果接入 `NLP` 或其它预测器，再在前端内部补预测状态和后端更新接口。

## 5. 前端设计

## 5.1 模块边界

前端顶层 `Frontend` 只例化：

- `NextPC`
- `ICache`
- `IRefill`
- `Queue(new FetchPacket, entries = 1, pipe = false, flow = false)` 作为 skid buffer

除这几个外，其余逻辑都在顶层完成，包括：

- redirect 优先级选择
- F0/F1/F2 流水寄存
- ICache 命中后的 32b 指令抽取
- miss 检测与 replay 生成
- 前后端 `ready` 断链

## 5.2 前端接口

建议接口改为：

```scala
class FrontendIO(implicit p: CoreParams) extends Bundle {
  val inst = Decoupled(new FetchPacket)
  val redirects = Input(Vec(5, Valid(new RedirectReq)))
  val bus = new TLBundleUH(/* refill only */)
}
```

这里只有两类对后端可见信号：

- `inst`
- `redirects`

没有独立 `flush` 信号。

## 5.3 前端三级时序

你认可的 `4.2` 时序保留，落成：

- `F0`：`NextPC` 输出 `reqPc`，向 ICache tag/data SRAM 发起访问。
- `F1`：ICache 返回 tag/data，完成命中判断和 32b 指令抽取。
- `F2`：若命中则将 `FetchPacket` 写入 `Queue`；若未命中则送入 `IRefill` 并发出 frontend miss replay redirect。

关键实现点：

- `F0/F1/F2` 都要带 `valid`。
- 任何 redirect 生效时，`F1/F2` 中年轻于 redirect 的指令都失效。
- `Queue` 满、`IRefill` 忙、ICache refill 占用 SRAM 时，前端停止推进。

## 5.4 NextPC 设计

`NextPC` 统一组合仲裁 5 类来源：

1. `seq pc + 4`
2. `Frontend Miss Replay`
3. `Jump Early Decode`，来自 D 级
4. `Branch / CSR / Uncached Flush`，来自 E 级
5. `Exception / Backend DCache Miss Replay`

未来扩展：

6. `NLP`

建议模块接口：

```scala
class NextPCIO(implicit p: CoreParams) extends Bundle {
  val redirects = Input(Vec(5, Valid(new RedirectReq)))
  val currentPc = Input(UInt(p.addrBits.W))
  val nextPc = Output(UInt(p.addrBits.W))
  val selected = Output(Valid(new RedirectReq))
}
```

当前优先级建议：

1. `Exception / Backend DCache Miss Replay`
2. `Branch / CSR / Uncached Flush`
3. `Jump Early Decode`
4. `Frontend Miss Replay`
5. `seq pc + 4`

原因：

- 越靠后流水级的请求越老。
- 你的前端 miss replay 是最年轻来源，必须被后端更老的控制流更新覆盖。

未来加入 NLP 时，NLP 不应高于任何已知正确的 redirect。

## 5.5 ICache 设计

ICache 维持 `2-way`、单端口 tag/data SRAM、refill 优先于 fetch。

建议接口：

```scala
class ICacheReq(implicit p: CoreParams) extends Bundle {
  val addr = UInt(p.addrBits.W)
}

class ICacheResp(implicit p: CoreParams) extends Bundle {
  val pc = UInt(p.addrBits.W)
  val hit = Bool()
  val waymask = UInt(p.icacheWays.W)
  val line = UInt((p.icacheLineBytes * 8).W)
}
```

实现建议：

- tag array：`SyncReadMem(sets, Vec(ways, UInt((tagBits + 1).W)))`
- data array：`SyncReadMem(sets, Vec(ways, UInt(lineBits.W)))`
- 每行 16B，支持从 line 中按 `pc(3,2)` 选 1 条 32b 指令
- 因为不支持 `C` 扩展，抽取逻辑固定按 4B 对齐

## 5.6 IRefill 设计

`IRefill` 是单独模块，负责：

- 接收一项 miss 描述符
- 对外发 TL-UH 读请求
- 接收返回数据
- 更新 ICache 的 tag/data array
- refill 完成后通知顶层生成 replay redirect

建议内部只支持 1 项在途 miss，保持前端控制简单。

接口示意：

```scala
class IRefillReq(implicit p: CoreParams) extends Bundle {
  val missPc = UInt(p.addrBits.W)
  val setIdx = UInt(log2Ceil(p.icacheSets).W)
  val tag = UInt((p.addrBits - log2Ceil(p.icacheSets) - log2Ceil(p.icacheLineBytes)).W)
  val replaceWay = UInt(log2Ceil(p.icacheWays).W)
}
```

顶层控制规则：

- `IRefill` 忙时禁止新 fetch。
- miss 总是 replay 到原始 `missPc`。
- refill 完成后立刻重新让 `NextPC` 看到 frontend miss replay 已清除。

## 5.7 Queue 代替 SkidBuf

不单独实现 `SkidBuffer` 模块，前端顶层直接使用 `Queue`：

```scala
val outQ = Module(new Queue(new FetchPacket, 1, pipe = false, flow = false))
```

使用原则：

- 只用于切断 `frontend.inst.ready` 到 `ICache.req` 的组合级连。
- redirect 生效时清掉 `F1/F2` 有效位；`Queue` 中若存在更年轻错误路径指令，也需要由前端顶层显式 squash。

如果 Chisel 原生 `Queue` 对定向清空不方便，可以在顶层再包一层 `valid` 控制，而不是额外建独立模块。

## 6. 后端设计修订

## 6.1 Backend 接口

后端不需要独立 `imemFault` 信号，接口收敛为：

```scala
class BackendIO(implicit p: CoreParams) extends Bundle {
  val in = Flipped(Decoupled(new FetchPacket))
  val redirects = Output(Vec(5, Valid(new RedirectReq)))
  val dmem = new TLBundleUH(/* dcache / uncached */)
}
```

## 6.2 Decode 设计

decode 参考：

- `docs/ref` 中的香山 `XSDecode` / `DecodeConstants`
- `docs/inst32`
- `docs/inst64`

建议沿用“`BitPat` 指令定义 + `ListLookup`/表驱动”风格，不走巨型 `switch`。

但对 `DecodeInfo` 做当前核的裁剪，不保留你明确不要的字段：

```scala
class DecodeInfo extends Bundle {
  val src1Type = UInt(3.W)
  val src2Type = UInt(3.W)
  val fuType = UInt(4.W)
  val fuOpType = UInt(8.W)
  val rfWen = Bool()
  val isRVT64 = Bool()
  val isRVT32 = Bool()
  val selImm = UInt(4.W)
  val isLoad = Bool()
  val isStore = Bool()
  val isBranch = Bool()
  val isJump = Bool()
  val isCsr = Bool()
  val isMul = Bool()
  val isDiv = Bool()
  val isAtomic = Bool()
  val isFence = Bool()
  val flushPipe = Bool()
  val illegal = Bool()
}
```

几个明确点：

- `fWen` 不保留。
- `xsTrap` 不保留。
- `isRTS` 改成 `isRVT64` / `isRVT32`。
- `flushPipe` 仍然保留，因为 `FENCE.I`、部分 CSR/系统指令仍然要触发控制流刷新。

`ExecuteUnit` 的接口层次也要明确：它消费的是已经结构化的 `DecodeInfo`，而不是零散展开的控制信号。建议执行级输入按下面组织：

```scala
class ExecuteIn(implicit p: CoreParams) extends Bundle {
  val pc = UInt(p.addrBits.W)
  val inst = UInt(32.W)
  val info = new DecodeInfo
  val src1 = UInt(p.xlen.W)
  val src2 = UInt(p.xlen.W)
  val imm = UInt(p.xlen.W)
  val rd = UInt(5.W)
  val isUncached = Bool()
}
```

这样做的目的有两个：

- 执行级只依赖 decode 的稳定抽象，不直接耦合 decode 内部编码细节。
- 后续扩展 `M/A/RVT` 指令时，只需要扩 `DecodeInfo` 和 `fuOpType` 定义，不需要在 execute 侧新增大量零散控制线。

## 6.3 Uncached 判定

你要求在 D 级完成 uncached 区域判定，然后打拍到 E 级处理，这个要写死在方案里：

- D 级基于 `rs1 + imm` 形成的地址候选判断是否命中 `uncachedRegions`
- 判定结果作为 `isUncached` 随指令进入 E 级
- E 级按 `isUncached` 触发 `Branch / CSR / Uncached Flush`

这里的重点是：

- D 级只做区域分类，不在 D 级直接改控制流
- E 级才是发 flush 的统一提交点

## 6.4 Scoreboard

Scoreboard 仍保留 `2 + 3` 结构，但 `FixedSlot` 精简：

```scala
class FixedSlot extends Bundle {
  val valid = Bool()
  val rd = UInt(5.W)
  val isLoad = Bool()
}

class LongSlot extends Bundle {
  val valid = Bool()
  val rd = UInt(5.W)
  val token = UInt(3.W)
}
```

不需要 `readyNext`：

- E slot 默认表示“下一拍可进入 W 语义”
- W slot 默认表示“本拍可前递/可写回”

Scoreboard 职责保持：

- D 级阻塞相关冲突
- 判断 E/W 级前递可行性
- 管理长延迟 rd 占用

旁路逻辑不要再额外抽成 `BypassNetwork` 模块，直接紧耦合在 D/E/W 代码里实现。

## 6.5 StoreQueue 与 Load Forward

这个点原方案漏掉了，现在补上：

- W 级已提交但尚未写入 DCache / 总线的 store，保存在 `StoreQueue`
- E 级 load 发射时，必须同时检查：
  - W 级当拍提交 store
  - `StoreQueue` 中所有更老 store

forward 规则：

- 按字节比较地址命中
- `mask` 粒度 forward
- 若 load 所需字节全部被命中 store 覆盖，则直接拼出返回数据
- 若只覆盖部分字节，则剩余字节再从 cache / 总线返回数据补齐

因此 `StoreQueue` 项必须至少携带：

```scala
class StoreQueueEntry(implicit p: CoreParams) extends Bundle {
  val addr = UInt(p.addrBits.W)
  val data = UInt(p.xlen.W)
  val mask = UInt((p.xlen / 8).W)
  val uncached = Bool()
}
```

## 6.6 Difftest

必须与现有 `Test.scala` 保持一致，顶层例化方式也参考它。

至少保留以下 5 个模块：

- `DiffArchEvent`
- `DiffPhyIntRegState`
- `DiffCSRState`
- `DiffInstrCommit`
- `DiffTrapEvent`

建议单独做 `commit` 侧信号收敛，但不一定拆独立目录。核心要求只有一个：

- 不能少例化任何一个，否则工程直接编译失败

接入时机建议进一步明确，不要等到“功能都写完再接”：

### Difftest 接入阶段 1

- 在 `WiredRV64S4Core` 顶层先把 5 个 `DifftestModule` 全部例化出来。
- 先允许大部分字段接 `dontCare` 或安全占位值。
- 保证工程从第一版顶层开始就满足 Difftest 的编译依赖。

### Difftest 接入阶段 2

- 当 `RegFile`、`CSRFile`、W 级提交路径完成后，接通：
  - `DiffPhyIntRegState`
  - `DiffCSRState`
  - `DiffInstrCommit`

这时目标是先让顺序提交路径能稳定产生最小可用的 commit 信息。

### Difftest 接入阶段 3

- 当异常、跳转、flush、replay 路径稳定后，再补全：
  - `DiffArchEvent`
  - `DiffTrapEvent`

这一步再把 trap、exceptionPC、interrupt、skip 等信息补完整。

这个顺序的原因是：

- Difftest 的“模块存在性”要求很早就要满足。
- Difftest 的“信号语义正确性”可以随着核心功能逐阶段补齐。
- 这样不会出现核心代码快成型时，再为了补 Difftest 接口大规模返工。

## 7. TileLink-UH 总线建议

核内不再引入自定义 `SimpleBus`。直接在 IRefill / LSU / DCache 对接 `TileLink-UH`。

建议：

- IRefill 单独占一个 TL-UH 主口，或者在顶层通过仲裁与 DCache 共用
- DCache / uncached LSU 走另一组请求源
- 如果共享一个主口，优先级建议：
  1. backend exception replay / uncached completion 相关事务
  2. DCache miss / store drain
  3. ICache refill

## 8. 顶层实现建议

`WiredRV64S4Core` 顶层建议包含：

- `Frontend`
- `Backend`
- `DifftestModule` 五件套
- I/D TL-UH 仲裁
- region 参数下发

例化方式需要参考 [Test.scala](/workspace/WiredRV/src/main/scala/wiredrv/Test.scala:1) 的 `DifftestModule.top(...)` 风格，而不是自己另起一套。

## 9. 实现顺序

保留你认可的五阶段节奏，但收敛成当前核需要的版本：

### 第 1 阶段

- `CoreParams`
- `FetchPacket`
- `RedirectReq`
- `Frontend` 骨架
- `Backend` 骨架
- 5 个 Difftest module 先占位例化，满足编译

### 第 2 阶段

- `NextPC`
- `ICache`
- `IRefill`
- 前端 `F0/F1/F2 + Queue`
- 顶层继续保留 Difftest 占位连接

### 第 3 阶段

- decode 表
- regfile
- scoreboard
- D/E/W 流水
- 接通 `DiffPhyIntRegState`、`DiffCSRState`、`DiffInstrCommit`

### 第 4 阶段

- DCache / LSU
- uncached 判定与 flush
- store queue + byte forward
- 补全 redirect/replay 相关 Difftest 语义

### 第 5 阶段

- `M`
- `A`
- 更完整 CSR / exception / replay
- 接通并校准 `DiffArchEvent`、`DiffTrapEvent`

## 10. 结论

按你现在的约束，这个核的方案重点不是“抽象得漂亮”，而是边界收紧：

- 前端只保留 `NextPC/ICache/IRefill/FrontendTop`
- NextPC 统一组合仲裁 5 类来源，并预留 NLP
- 前端 miss 只在前端内部处理，不传递给后端
- 当前版本不实现分支预测，因此 `jump/target` 只保留接口语义，不需要后端更新接口
- decode 借鉴香山和 Rocket 的表驱动风格，但字段裁剪到当前核需要
- Execute 消费 `DecodeInfo` 而不是零散控制信号
- uncached 在 D 级判定、E 级生效
- store 对后续 load 做按字节 forward
- 总线直接用 TL-UH
- Difftest 维持 5 模块完整接入，并按占位例化 -> 提交接通 -> 异常校准的顺序推进

这样文档已经可以直接指导骨架编码，不需要再靠上一版那些面向通用核的附加模块。
