# WiredRV64S4

Wired RV64 S4 是一款使用 Chisel 开发的四级流水 RV64 处理器，计划支持 RV64IMA 及 CSR 拓展。

处理器采用紧凑的四级流水设计，分别是取指（F）、解码及读寄存器级（D）、访存及执行级（E）、写回级（W）。

对五级流水简化做改进，提前 M 级并与 D/E 级融合，适配现代工艺特征（组合逻辑延迟较低，目标频率为 1GHz）的同时提高处理器 IPC。

由于简化后的流水线分支惩罚较低，仅做永远不跳转的性能也仅有 2 拍的条件分支惩罚（1 拍的无条件跳转惩罚），处理器可以不实现分支预测器，留待后续优化。

处理器的实现分为前端和后端，前端包含 NPC 与 ICache 模块。

在前端的第 0 周期，NPC 模块产生的组合逻辑 PC 值被送入 ICache 并行访问 SRAM Tag 与 Data。

在前端的第 1 周期，处理器使用获取到的 Cache Tag 生成两路指令的 Hit 信号，与 Cache Data 获取到的两路指令数据一起打拍送入下一级（指令可根据 Hit 信号，在本级做一次 Mux 处理，选出有可能命中的指令）

前端第 1 周期的输出额外接一个 Skid Buffer，用于控制暂停逻辑；额外接一个一项的 Refill Buffer 用于执行重填。

当 Skid Buffer 满时，NPC 模块和 Cache 模块暂停。
当 Refill Buffer 非空时，NPC 模块和 Cache 模块暂停。

前端命中信号到达前端第 2 周期，如若未命中，则将请求压入 Refill Buffer，并立即产生重定向请求，定向到当前 PC。

Refill Buffer 非空时，激活前端的 Refill 逻辑，自动发出总线请求填充 ICache Tag 和 Data。

ICache Tag 和 Data 均为单端口 SRAM，根据 Refill Buffer 忙碌情况做固定优先级仲裁（优先 Refill）。

整体前端实现，其实就是围绕 ICache 的一段紧耦合流水线和重填状态机。

前端向后端，提供一个流式的 32b 指令握手接口，valid-ready 握手。指令信号中额外附加指令无效信号，用于后端为无效请求发起重定向请求。

后端向前端，提供一组 Valid 接口（Valid 接口数组）的非阻塞重定向接口，有效时立即重定向到目标 PC 并刷洗前端第 1 周期的请求。该请求以组合逻辑形式在 NPC 模块中进行仲裁，保证当前周期送入 SRAM 进行访问。

前端对多个前递源采用优先级选择，选择最靠后的最老指令的重定向请求而忽略较新的重定向请求。

后端为三级流水，第一级是 D 级。后端对前端传来的一条指令，做解码，解码同时并行访问 RF 和 Scoreboard（三个读口分别处理 rs1、rs2、rd）。

Scoreboard 实现为一个 2 + 3 项的 CAM 电路，前 2 项记录当前在 E 级、W 级执行的 ALU 或者访存指令，即预期固定拍数后可以取得数据的指令，固定周期写回记录。

后 3 项则记录长周期指令的写回寄存器号，比如乘除法指令、原子指令、Uncached 读取指令等，不定周期写回记录。

注意对于 Uncached 读取指令，由于到 E 级才能完成判定该指令访问是否在 Cache 中（通过配置划分固定 Uncached 区域），因此在 D 级假设所有普通访存指令均为 Cache 读取指令，写入第一类的 CAM 表项中。对于发现是 Uncached 的指令，处理器将该指令信息追加到第二类 Scoreboard 中，并做 Flush 操作（从 pc+4 重新开始执行）以消除错误预测影响。

在 D 级的四个 Scoreboard CAM 表项，记录了当前正在运行还未写回的所有通用寄存器号。指令会检查写回寄存器号和读取寄存器号和三个不定周期写回记录是否相同（且非 0）。若满足则阻塞该指令不发射。

额外检查读取寄存器号和定周期 E 级写回记录是否相同。对访存指令地址来说，如和 E 级相同则阻塞；对 ALU 指令和访存指令数据来说，如和 E 级相同则标记可转发，在下一拍做数据前递。

对所有指令来说，检查读取寄存器号和 W 级写回记录是否一致，若一致则做数据前递。

在同一拍，将 RF 得到的 rs1 结果做完 W 级前递加上访存指令的偏移送入 DCache 的 SRAM 端口开始访存。同时准备 Cache 的写数据。注意 Cache 写数据也可以来自 W 级的转发。

E 级实现 DCache Tag 的命中检查逻辑，并实现 ALU。注意这一级 ALU 的输入源可以来自 W 级的转发。E 级额外需要检查处理器状态的更新情况。如遇到处理器状态控制流改变指令（如写入 CSR 或者 Branch、Jump、或者访存为 Uncached），则执行重定向或者 Flush 操作刷洗管线。

W 级实现处理器状态的更新和异常检查。如访存未命中缓存且非 Uncached 则触发 replay 重定向并将请求压入 Refill buffer。如发生异常则触发 Exception Jump 跳转到异常处理入口并更新 CSR 状态。如无异常，则说明该指令确认可以提交，则完成 DCache 写入操作（压入 Write Queue）、RF 写入操作、不定周期（协处理器指令、Uncached、原子、乘除）指令发射。

特别的是，从 W -> D 的数据转发，不用检查是否出现异常，仅实际写回寄存器时需要这个操作。因为如果发生异常，则相应的被前递指令将会被冲刷。

不定周期指令的发射，所有不定指令写回共享一个寄存器写口，并需要仲裁。

通用寄存器为 3 读 2 写，1 个写口由固定延迟指令专用、1 个写口由不定周期指令专用。
